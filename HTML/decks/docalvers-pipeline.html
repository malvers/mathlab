Warum GitHub Pages allein nicht reicht

GitHub Pages liefert nur feste Dateien — für jeden Besucher dieselben

Es kann nichts speichern: kein Testergebnis, keine Planänderung, keine Notiz

Es kann nichts geheim halten: Das Repo ist öffentlich — jeder Schlüssel darin auch

Große Dateien im Git bleiben für immer in der History — jede einzelne Fassung

Deshalb gibt es daneben Supabase für Daten und Cloudflare R2 für große Dateien

Supabase — die Datenbank hinter der Seite

Im Kern eine PostgreSQL-Datenbank: Tabellen, Zeilen, SQL — wie in LB 1

Der Browser spricht sie direkt an, über eine REST-Schnittstelle im Internet

Ihr Schlüssel steht offen im JavaScript — geschützt wird jede Zeile (RLS, 115 Regeln)

Edge Functions sind kleiner Server-Code: Sie rufen z. B. Solitas Stimme oder Claude — mit Schlüsseln, die geheim bleiben

Realtime: Der Fernstift auf dem Tablet malt live ins Deck auf dem Beamer

Nicht verzagen, Doc Alvers fragen!

Cloudflare R2 — der Speicher für große Dateien

R2 speichert Objekte: eine Datei unter einem Schlüssel, z. B. og/buch-mathe9.jpg

Hier liegt, was Git nicht tragen soll: Videos, Android-Apps, das 3D-Modell des Avatars

Und die Vorschaubilder, die beim Teilen eines Links erscheinen — für 1.758 Seiten

Hochgeladen wird vom Mac mit einem Skript: media_publish.mjs

Das Herunterladen kostet bei R2 keine Gebühr — egal, wie viele kommen

Nicht verzagen, Doc Alvers fragen!
