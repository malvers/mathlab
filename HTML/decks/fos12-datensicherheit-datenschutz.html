Passwörter

Niemals im Klartext, niemals selbst gebaut

Nicht verzagen, Doc Alvers fragen!

So werden Passwörter behandelt

<?php
// Registrierung: nur den Hash speichern, nie das Passwort
$hash = password_hash($_POST['passwort'], PASSWORD_DEFAULT);
$stmt = $db->prepare('INSERT INTO nutzer (name, pwhash) VALUES (?, ?)');
$stmt->execute([$_POST['name'], $hash]);

// Anmeldung: vergleichen, nicht entschluesseln
$stmt = $db->prepare('SELECT pwhash FROM nutzer WHERE name = ?');
$stmt->execute([$_POST['name']]);
$zeile = $stmt->fetch();

if ($zeile && password_verify($_POST['passwort'], $zeile['pwhash'])) {
    session_start();
    $_SESSION['nutzer'] = $_POST['name'];
}
?>

Nicht verzagen, Doc Alvers fragen!

Was daran wichtig ist

Ein Hash lässt sich nicht zurückrechnen — man kann nur vergleichen

password_hash würzt jedes Passwort mit einem Zufallswert (Salt) — gleiche Passwörter, verschiedene Hashes

Niemals eine eigene Verschlüsselung erfinden: dafür gibt es geprüfte Funktionen

Niemals ein Passwort im Quelltext, in einem Kommentar oder in einer Beispieldatei

Und im Schulprojekt: Passwörter nur für erfundene Testkonten

Eure Sicherheitscheckliste

NrPrüfpunkterledigt
1Jede Datenbankabfrage mit Nutzereingabe benutzt prepare____
2Jede Ausgabe fremder Daten geht durch htmlspecialchars____
3Jede Eingabe wird auf dem Server geprüft (Typ, Bereich, Länge)____
4Passwörter nur als Hash, kein Klartext im Code oder in der DB____
5Keine echten personenbezogenen Daten im Projekt____
6Datenschutzhinweis auf der Seite: was wird gespeichert, wozu____
7Datenbankdatei nicht über die URL erreichbar____
8Sicherungskopie vorhanden und wiederherstellbar____

Diese acht Punkte gehören ausgefüllt in die Projektdokumentation

Zu jedem Punkt: eine Zeile, wie ihr ihn umgesetzt habt — nicht nur ein Häkchen
