Kontrollierte Redundanz

Nicht jede Redundanz ist ein Fehler — manche ist beabsichtigt

Ein Index ist Redundanz: dieselben Werte noch einmal, sortiert

Eine Sicherungskopie ist Redundanz — und lebensrettend

Entscheidend ist, dass das DBMS sie pflegt, nicht der Mensch

Gefährlich ist nur die unkontrollierte Redundanz in den Nutzdaten

Die Integritätsarten

Vier Ebenen, vier Regeln

Welche Integrität wovor schützt

ArtRegelim SQL
Domänenintegritätder Wert passt zum Datentyp und WertebereichDatentyp, CHECK
Entitätsintegritätjede Zeile ist eindeutig, Schlüssel nicht NULLPRIMARY KEY
Referentielle Integritätjeder Verweis zeigt auf eine vorhandene ZeileFOREIGN KEY
Semantische Integritätfachliche Regeln der MiniweltCHECK, Trigger

Die ersten drei kann jedes DBMS automatisch durchsetzen

Die vierte muss man formulieren — sie steht in keinem Standard

Constraints im DBMS setzen

CREATE TABLE Belegung (
    snr  INTEGER NOT NULL REFERENCES Schueler(snr),
    knr  INTEGER NOT NULL REFERENCES Kurs(knr),
    note INTEGER CHECK (note BETWEEN 1 AND 6),
    PRIMARY KEY (snr, knr)
);

ALTER TABLE Kurs
  ADD CONSTRAINT stunden_positiv CHECK (stunden > 0);

Regeln gehören in die Datenbank

Auf dieselbe Datenbank greifen mehrere Programme zu

Eine Regel im Programm gilt nur für dieses Programm

Eine Regel im DBMS gilt für jeden Zugriff, auch für den von Hand

Und sie überlebt den Austausch der Anwendung

Faustregel: fachliche Regeln so nah wie möglich an den Daten

Fun Facts: Integrität

ACID wurde 1983 von Härder und Reuter geprägt — beide aus Deutschland

Manche verteilten Systeme geben Konsistenz bewusst auf: das nennt man BASE

Der CAP-Satz sagt: von Konsistenz, Verfügbarkeit und Partitionstoleranz gibt es nur zwei

Ein Trigger ist Programmcode, den das DBMS bei bestimmten Änderungen selbst ausführt

Trigger sind mächtig und gefürchtet: sie wirken unsichtbar, wenn niemand sie dokumentiert
