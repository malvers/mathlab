Mehrere Parameter, ein Rückgabewert

def note_aus_punkten(punkte, maximum):
    prozent = punkte / maximum * 100
    if prozent >= 85:
        return 1
    elif prozent >= 70:
        return 2
    elif prozent >= 55:
        return 3
    return 4

print(note_aus_punkten(48, 60))     # Argumente in der Reihenfolge der Parameter
print(note_aus_punkten(maximum=60, punkte=48))   # oder benannt, dann egal

return beendet die Funktion — sofort

Ist return erreicht, springt die Funktion zurück; alles danach läuft nicht mehr

Deshalb braucht das Beispiel oben kein else — jeder Treffer verlässt die Funktion

Eine Funktion ohne return gibt in Python None zurück

Mehrere Werte gehen auch: return kleinster, groesster liefert ein Wertepaar

Aufteilen des Paars beim Aufruf: a, b = grenzen(zahlen)

    return 3.14159 * r * r        # gibt es heraus, zeigt nichts an

Die Faustregel

Rechnen und Ausgeben trennen: die Funktion rechnet, das Hauptprogramm zeigt an

Nur so lässt sich die Funktion testen — man vergleicht ihren Rückgabewert mit dem Sollwert

Und nur so lässt sie sich wiederverwenden, etwa in einer Schleife oder Datei

print in einer Rechenfunktion ist fast immer ein Zeichen für unfertiges Zerlegen

Ausnahme: Funktionen, deren Zweck die Ausgabe ist — die heißen dann auch so

Lokal und global

zaehler = 0                  # global

def erhoehen(wert):
    zaehler = wert + 1       # LOKAL - eine eigene, neue Variable
    return zaehler

print(erhoehen(5))           # 6
print(zaehler)               # 0  - das globale zaehler blieb unberuehrt

Warum das gut so ist

Alles in einer Funktion Angelegte ist lokal und verschwindet beim Verlassen

Damit kann eine Funktion nichts kaputt machen, was sie nichts angeht

Was sie braucht, kommt als Parameter herein; was sie liefert, geht als return hinaus

global gibt es, ist aber fast immer die falsche Antwort — es hebt genau diesen Schutz auf

Diese Trennung heißt Kapselung und ist der Kern jeder Modularisierung

Vorher: ein Block, der alles macht

noten = []
eingabe = int(input('Note (0 = Ende): '))
while eingabe != 0:
    noten.append(eingabe)
    eingabe = int(input('Note (0 = Ende): '))

summe = 0
beste = noten[0]
for n in noten:
    summe = summe + n
    if n < beste:
        beste = n
print(round(summe / len(noten), 2), beste)

Nachher I: die Eingabe wird eine Funktion

def noten_einlesen():
    werte = []
    eingabe = int(input('Note (0 = Ende): '))
    while eingabe != 0:
        werte.append(eingabe)
        eingabe = int(input('Note (0 = Ende): '))
    return werte

Nachher II: rechnen und Hauptprogramm

def mittelwert(werte):
    return sum(werte) / len(werte)

def beste_note(werte):
    return min(werte)

noten = noten_einlesen()
print(round(mittelwert(noten), 2), beste_note(noten))

Fun Facts: Modularisierung

David Parnas formulierte 1972 das Prinzip: ein Modul verbirgt eine Entwurfsentscheidung

DRY — „Don't repeat yourself“ — stammt aus „The Pragmatic Programmer“ (1999)

Eine Python-Funktion ohne return liefert None — der häufigste Grund für „warum ist das leer?“

Eine veränderliche Vorgabe wie def f(liste=[]) merkt sich Änderungen über Aufrufe hinweg — eine der bekanntesten Python-Fallen

Funktionen sind in Python Werte: man kann sie in Variablen legen und weitergeben
