        if liste[i] == gesucht:

Binäre Suche — setzt eine sortierte Liste voraus

def suche_bin(liste, gesucht):
    links, rechts = 0, len(liste) - 1
    while links <= rechts:
        mitte = (links + rechts) // 2
        if liste[mitte] == gesucht:
            return mitte
        elif liste[mitte] < gesucht:
            links = mitte + 1     # rechte Haelfte
        else:
            rechts = mitte - 1    # linke Haelfte
    return -1

Selectionsort: das Minimum nach vorn holen

def selectionsort(a):
    for i in range(len(a) - 1):
        kleinster = i
        for j in range(i + 1, len(a)):
            if a[j] < a[kleinster]:
                kleinster = j
        a[i], a[kleinster] = a[kleinster], a[i]
    return a

Was das über den Aufwand sagt

Verdoppelt man die Elemente, vervierfacht sich die Vergleichszahl

Man sagt: der Aufwand wächst quadratisch, geschrieben O(n²)

Bei der binären Suche wächst er logarithmisch: O(log n)

Bei der sequenziellen Suche linear: O(n)

Gute Sortierverfahren wie Mergesort schaffen O(n · log n)

Fun Facts: Suchen und Sortieren

Die binäre Suche ist berüchtigt: Jon Bentley fand, dass 90 % der Programmierer sie fehlerhaft schreiben

Der häufigste Fehler ist eine falsche Grenze — mitte + 1 statt mitte

Ein Überlauf bei (links + rechts) war jahrelang in Javas Standardbibliothek

Bogosort mischt zufällig, bis es passt — der schlechteste Algorithmus mit eigenem Namen

Pythons sorted() benutzt Timsort, entwickelt 2002 von Tim Peters
