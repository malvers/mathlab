Kapitel 02

Die Anforderungsliste

Was das Produkt können muss

Nicht verzagen, Doc Alvers fragen!

So sieht eine Anforderungsliste aus

NrAnforderungArt
1Das Spiel startet mit einem Klick auf die grüne FlaggeMuss
2Der Spieler steuert die Figur mit den PfeiltastenMuss
3Punkte werden gezählt und angezeigtMuss
4Bei drei Treffern ist das Spiel vorbeiMuss
5Es gibt HintergrundmusikKann
6Es gibt drei SchwierigkeitsstufenKann

Muss heißt: ohne das ist das Produkt nicht fertig. Kann heißt: wenn Zeit bleibt

Jede Anforderung ist überprüfbar formuliert — man kann sie hinterher abhaken

Nicht verzagen, Doc Alvers fragen!

Gut und schlecht formuliert

Schlecht: „Das Spiel soll Spaß machen“ — das kann niemand prüfen

Gut: „Nach jedem Treffer erscheint eine Meldung“ — das sieht man

Schlecht: „Es soll schön aussehen“

Gut: „Der Hintergrund wechselt ab Stufe 2“

Faustregel: Wenn man ja oder nein antworten kann, ist es gut formuliert

Kapitel 03

Die kleinste Version

Erst laufen lassen, dann verschönern

Nicht verzagen, Doc Alvers fragen!

Warum man klein anfängt

Eine kleinste Version enthält nur die Muss-Anforderungen — sonst nichts

Sie läuft früh, und ab da könnt ihr jede Woche etwas zeigen

Wer alles gleichzeitig baut, hat bis zuletzt gar nichts Lauffähiges

Und wenn die Zeit knapp wird, habt ihr trotzdem ein fertiges Produkt

Profis nennen das MVP — die kleinste brauchbare Fassung

Nicht verzagen, Doc Alvers fragen!

Eine gute Anforderung kann man abhaken. Wenn nicht ja oder nein darauf passt, ist sie keine Anforderung, sondern ein Wunsch.
